feat(serve): advertise per-model capabilities on /v1/models from the serving provider

Adds `Capabilities []string` (json:"capabilities,omitempty") to compatModel
(serve_compat.go), populated from the SERVING provider's
Capabilities().Capabilities — same #518 contract context_length already
uses: absent means unknown, NEVER a guessed list. An entry whose provider
declares an empty Capabilities slice, or that has no resolvable provider
(static entry with nothing configured), omits the field entirely rather than
emitting `[]`.

- capabilityStrings() converts []Capability -> []string, nil in/nil out.
- servingProviderCapabilities/frontierCapabilities/localAliasCapabilities
  mirror servingProviderContextLength/frontierContextLength/
  localAliasContextLength exactly — same provider resolution, one field
  over, so context_length and capabilities can never disagree about which
  provider is serving an id.
- modelEntryFor (live-enumerated ids, both bare claude and composite
  provider/model) now also carries p.Capabilities().Capabilities.
- foreground/deliberation aliases and the static claude-sonnet-4-6 /
  claude-opus-4-7 / claude-haiku-4-5-20251001 / eclipse-26b ids inherit
  capabilities from the resolved serving provider, exactly mirroring how
  they already inherit context_length — same predicate, same lookup.

Provider Capabilities() changes (every provider whose declared list changed
is disclosed here per the PR instructions):
  - ClaudeCodeProvider (provider_claudecode.go): added CapVision. It drives
    the same claude-* family (sonnet/opus/haiku) as claude-oauth /
    AnthropicProvider, both of which already declare CapVision — the family
    is uniformly multimodal, so omitting it here was the actual gap #640
    reports (Hermes could not discover vision through the CLI-backed
    provider).
  - CodexProvider (provider_codex.go): added CapVision. Every model in
    codex's catalog is gpt-* family; the gpt-4o/gpt-5 line is multimodal.
  - claude-oauth (provider_claudeoauth.go) and AnthropicProvider
    (provider_anthropic.go): UNCHANGED — both already declared CapVision.
  - OpenAICompatProvider / LM Studio (provider_openai.go): UNCHANGED. Its
    native GET /api/v0/models row (lmsModelRow, provider_lms_model_state.go)
    exposes id/state/loaded_context_length/max_context_length/type — no
    vision or capability flag of any kind. There is no per-model upstream
    field to plumb, so capabilities for lmstudio-* ids come from the
    provider-level Capabilities() (currently {streaming, json_output}, no
    vision) rather than a fabricated per-model signal. Confirmed live
    against Darkstar's :1234 per the existing comment in
    provider_lms_model_state.go.
  - PiProvider (provider_pi.go): UNCHANGED per the issue's explicit
    instruction (backend-dependent, left alone).

Alias behavior disclosed as required: the intent aliases foreground and
deliberation, and the static claude-* / eclipse-26b ids, DO get
capabilities (mirroring how they already get context_length via
frontierContextLength/servingProviderContextLength). The short convenience
aliases (sonnet/opus/haiku/fable/claude) are NOT emitted in /v1/models at
all today — confirmed by a throwaway probe test before implementing: only
foreground, deliberation, local, and the three static claude-* ids appear
in data[]. They resolve purely at request time via ResolveModelRequest /
intentAliases in resolve.go and never enter compatModel to begin with, so
there is no context_length path for them today either — this PR does not
invent one, matching the instruction to mirror existing behavior exactly.

Tests (serve_compat_models_test.go, stub-lister pattern):
  - TestHandleModels_CapabilitiesPropagated: a stub with
    Capabilities()=[vision,tool_use] yields
    "capabilities":["vision","tool_use"] on its live composite id (raw JSON
    substring assertion + decoded struct assertion).
  - TestHandleModels_CapabilitiesAbsentIsOmitted: a stub with nil
    Capabilities yields NO "capabilities" key on the wire (raw JSON
    substring assertion).
  - TestHandleModels_CapabilitiesFrontierAliasesMatchProvider: a claude-oauth
    stub with [vision,tool_use,streaming] propagates that list identically
    to foreground, deliberation, and all three static claude-* ids.
  - TestHandleModels_CapabilitiesAbsentOnAliasesWhenProviderDeclaresNone:
    the negative case — a claude-oauth stub with nil Capabilities omits
    "capabilities" on every alias/static entry.
  - modelsResponseModel (resolve_test.go) gained a Capabilities []string
    field so the existing G2 test-decode helper can assert on it too.
